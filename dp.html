01 — Intent

What is Proxy?

The Proxy pattern provides an intermediary that controls access to another object.

🎯

Intent

Proxy is a structural design pattern that provides a substitute or placeholder for another object. The proxy can perform additional work such as access control, lazy initialization, caching, logging, or remote communication before delegating to the real object.

02 — Terminology

Also Known As

🔄

Surrogate

An object that acts on behalf of another object.

📦

Placeholder

An object that represents the real object until it is needed.

🛡️

Intermediary

A layer between the client and the actual object.

03 — Motivation

Why do we need Proxy?

❌ Without Proxy

  • The client directly accesses the expensive or sensitive object.
  • Security checks may be mixed with business logic.
  • Repeated expensive operations may not be controlled.
  • The client becomes more dependent on implementation details.

✅ With Proxy

  • Access can be checked before the real object is used.
  • Lazy initialization can delay expensive creation.
  • Caching can avoid repeated work.
  • Logging and monitoring can be added transparently.
04 — Applicability

When should you use Proxy?

⚡

Lazy Loading

Create an expensive object only when it is actually required.

🔐

Access Control

Allow or deny operations before forwarding them.

💾

Caching

Store and reuse previously obtained results.

🌐

Remote Proxy

Represent an object that exists in another process or machine.

📝

Logging

Record requests before delegating them.

🛡️

Protection

Restrict access to sensitive operations.

05 — Participants

Participants

👤

Client

Uses the Subject interface and does not need to know whether it is using a Proxy or RealSubject.

📋

Subject

Defines the common operations implemented by both Proxy and RealSubject.

🛡️

Proxy

Implements Subject, controls access, and contains a reference to the RealSubject.

⚙️

RealSubject

Contains the actual implementation of the requested operations.

06 — Structure

This structure follows the reference UML: Client depends on Subject; Proxy and RealSubject realize Subject; Proxy contains RealSubject.

interface BankAccount {

    void getBalance();

    void withdraw(double amount);
}


class RealBankAccount implements BankAccount {

    private double balance = 50000;

    @Override
    public void getBalance() {
        System.out.println(
            "Current Balance: ₹" + balance
        );
    }

    @Override
    public void withdraw(double amount) {

        if (amount <= balance) {

            balance -= amount;

            System.out.println(
                "Withdrawal successful: ₹" + amount
            );

            System.out.println(
                "Remaining Balance: ₹" + balance
            );

        } else {

            System.out.println(
                "Insufficient balance"
            );
        }
    }
}


class BankAccountProxy implements BankAccount {

    private RealBankAccount realAccount;

    private String username;

    private boolean authenticated;


    public BankAccountProxy(
        String username,
        boolean authenticated
    ) {
        this.username = username;
        this.authenticated = authenticated;
    }


    private boolean checkAccess() {

        System.out.println(
            "Checking access for: " + username
        );

        return authenticated;
    }


    @Override
    public void getBalance() {

        if (!checkAccess()) {

            System.out.println("Access denied!");
            return;
        }

        if (realAccount == null) {

            realAccount = new RealBankAccount();

            System.out.println(
                "Real bank account created."
            );
        }

        realAccount.getBalance();
    }


    @Override
    public void withdraw(double amount) {

        if (!checkAccess()) {

            System.out.println("Access denied!");
            return;
        }

        if (realAccount == null) {
            realAccount = new RealBankAccount();
        }

        realAccount.withdraw(amount);
    }
}


public class Main {

    public static void main(String[] args) {

        BankAccount account =
            new BankAccountProxy(
                "Priya",
                true
            );

        account.getBalance();

        System.out.println();

        account.withdraw(5000);

        System.out.println();

        account.getBalance();
    }
}
from abc import ABC, abstractmethod


class BankAccount(ABC):

    @abstractmethod
    def get_balance(self):
        pass

    @abstractmethod
    def withdraw(self, amount):
        pass


class RealBankAccount(BankAccount):

    def __init__(self):
        self.balance = 50000

    def get_balance(self):
        print(f"Current Balance: ₹{self.balance}")

    def withdraw(self, amount):

        if amount <= self.balance:

            self.balance -= amount

            print(
                f"Withdrawal successful: ₹{amount}"
            )

            print(
                f"Remaining Balance: ₹{self.balance}"
            )

        else:
            print("Insufficient balance")


class BankAccountProxy(BankAccount):

    def __init__(self, username, authenticated):

        self.username = username
        self.authenticated = authenticated
        self.real_account = None

    def check_access(self):

        print(
            f"Checking access for: {self.username}"
        )

        return self.authenticated

    def get_balance(self):

        if not self.check_access():

            print("Access denied!")
            return

        if self.real_account is None:

            self.real_account = RealBankAccount()

            print(
                "Real bank account created."
            )

        self.real_account.get_balance()

    def withdraw(self, amount):

        if not self.check_access():

            print("Access denied!")
            return

        if self.real_account is None:
            self.real_account = RealBankAccount()

        self.real_account.withdraw(amount)

#include <iostream>

using namespace std;


class BankAccount {

public:
    virtual void getBalance() = 0;
    virtual void withdraw(double amount) = 0;

    virtual ~BankAccount() {}
};


class RealBankAccount : public BankAccount {

private:
    double balance = 50000;

public:

    void getBalance() override {

        cout << "Current Balance: ₹"
             << balance << endl;
    }

    void withdraw(double amount) override {

        if (amount <= balance) {

            balance -= amount;

            cout << "Withdrawal successful: ₹"
                 << amount << endl;

            cout << "Remaining Balance: ₹"
                 << balance << endl;

        } else {

            cout << "Insufficient balance"
                 << endl;
        }
    }
};


class BankAccountProxy : public BankAccount {

private:
    RealBankAccount* realAccount = nullptr;

    string username;

    bool authenticated;

    bool checkAccess() {

        cout << "Checking access for: "
             << username << endl;

        return authenticated;
    }

public:

    BankAccountProxy(
        string name,
        bool auth
    ) {
        username = name;
        authenticated = auth;
    }


    void getBalance() override {

        if (!checkAccess()) {

            cout << "Access denied!"
                 << endl;

            return;
        }

        if (realAccount == nullptr) {

            realAccount =
                new RealBankAccount();

            cout <<
                "Real bank account created."
                << endl;
        }

        realAccount->getBalance();
    }


    void withdraw(double amount) override {

        if (!checkAccess()) {

            cout << "Access denied!"
                 << endl;

            return;
        }

        if (realAccount == nullptr) {
            realAccount =
                new RealBankAccount();
        }

        realAccount->withdraw(amount);
    }
};


int main() {

    BankAccount* account =
        new BankAccountProxy(
            "Priya",

}

10 — Consequences

Advantages & Disadvantages

✅ Advantages

• Controls access to another object

• Supports lazy initialization

• Enables caching

• Adds security and logging without changing the RealSubject

• Keeps client code independent from object creation details

⚠️ Disadvantages

• Adds an additional abstraction layer

• Can increase code complexity

• May add processing overhead

• Debugging can involve an extra object

• A poorly designed proxy can become difficult to maintain
